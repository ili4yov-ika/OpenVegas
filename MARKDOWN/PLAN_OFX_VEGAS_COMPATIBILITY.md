# План устранения расхождения OFX с VEGAS Pro

## Контекст

При отладке `vegas220.exe` в Ghidra/CDB установлено, что VEGAS Pro 22:

- создаёт и повторно использует контекст модуля для одного OFX-бинарника;
- вызывает `Load`, `Describe` и `DescribeInContext` в определённом порядке;
- после отказа бинарника на `Load` не продолжает описывать остальные эффекты этого файла;
- учитывает списки `OFX Excluded Plugins` и `OFX Thread Unsafe Plugins`.

OpenVegas до этой корректировки проверял отказ только после попытки `Load`: `failedBinaries` защищал последующие кадры, но каталогизация могла ранее вызвать загрузчик и действия OFX. При установленных нескольких поколениях VEGAS это позволяло неподходящему `Vfx1.ofx` попасть в раннюю discovery-цепочку.

## Цели

- Отсекать известный excluded/unsafe OFX до `Load`, `Describe` и `DescribeInContext`.
- Сохранять выбор альтернативного бинарника, если выбранный каталогом файл не разрешён или не загрузился.
- Дедуплицировать поведение на всех входах OFX-хоста и оставлять диагностическую причину в `OPENVEGAS_OFX_TRACE`.
- Не отключать автоматически `Vfx1.ofx` и не подменять реальный рендер эмуляцией.

## Реализация

- [x] Добавить единый policy gate в `OfxHost.cpp`.
- [x] Поддержать правила из `QSettings` (`plugins/ofxExcluded`, `plugins/ofxUnsafe`) и диагностические переменные окружения `OPENVEGAS_OFX_EXCLUDED`, `OPENVEGAS_OFX_UNSAFE`. Значения разделяются `;` или `,`; `QStringList` поддерживается напрямую.
- [x] Сопоставлять абсолютный путь, имя `.ofx`, имя `.ofx.bundle`, очищенное имя bundle и `effectId` без учёта регистра.
- [x] Проверять правило до действий в `effectIndexMap`, `enumerateEffects`, `describeContexts` и `Impl::ensureModule`.
- [x] Не добавлять исключённый effect в индексную карту и каталог.
- [x] Оставить `failedModules`/`failedBinaries` как отдельную защиту для фактических отказов загрузки; при отказе сохранять переход к `instantiateFromAlternate`.
- [x] Добавить trace-сообщение с именем бинарника и причиной пропуска.

## Проверка

- [x] Регрессионный тест: бинарник `Gain.ofx` исключается до загрузки.
- [x] Регрессионный тест: отдельный `effectId` исключается до загрузки.
- [x] Существующий тест `Gain.ofx` сохраняет allow-by-default и реальный render path.
- [x] Собрать `openvegas_media_tests` и запустить адресные OFX policy/regression тесты. Полный фильтр `[ofx]` дополнительно затрагивает установленные VEGAS-плагины и существующие интеграционные сценарии, поэтому не является изолированной проверкой этого изменения.
- [x] Debug-трасса ранее подтвердила рабочую цепочку `MagixAiFx.ofx` (`Load -> Describe -> DescribeInContext`); policy gate добавляет trace-причину до OFX action для исключённого бинарника.

## Ограничения и дальнейшая работа

Policy gate не может перехватить произвольный crash внутри DLL до возврата из `Load`; это отдельная задача изоляции/SEH и должна добавляться только после воспроизводимого теста. Для текущего расхождения безопасный порядок такой: раннее правило исключения, кэш отказа бинарника, затем выбор совместимого alternate binary.

Ключи конфигурации намеренно не содержат встроенного `Vfx1.ofx`: пользователь должен иметь возможность использовать основной плагин после проверки его совместимости.
